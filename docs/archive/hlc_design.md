# 상위제어기(HLC) 설계 문서 — Go1 재난 미로 내비게이션

> 환경: Colab + MJX(MuJoCo XLA), Unitree Go1
> 전제: LLC = Walk These Ways(WTW) 공개 체크포인트 `pretrain-v0`, **8차원 연속 명령** `(vx, vy, v_yaw, height, step_freq, footswing, pitch, stance_width)` 추종. gait는 **trot 고정**(§5.1).
> ⚠️ **WTW의 명령 인터페이스는 15D이지만, 배포된 가중치가 실제로 학습한 차원은 그보다 적다.** `duty`·`roll`은 상수로 고정된 채 학습되어 조작 불가, gait 파라미터는 `{0, 0.5}`로 양자화되어 이산 4종. 상세와 근거는 §5.1 및 `command_scale_guide.md` 참조. (`gait_offset/bound`는 gait 프리셋에 종속, `stance_length`·`aux`는 고정)
> 목표: 틈(gap), 외나무다리, 터널, 경사로, 좁은 틈새가 포함된 미로를 통과해 목표지점 도달
> Sim-only (실기 이식 없음)

## 0. 핵심 설계 결정 (논의 확정 사항)

| 결정 | 내용 |
|------|------|
| 역할 분리 | **플래너(BFS) = 거시적 방향 지시, PPO = 지형 돌파·정밀 정렬, LLC = 보행 실행** |
| 유도 방식 | BFS 거리장의 **기울기 방향(유도 벡터)을 정책 관측으로 직접 제공** (직선 방위 아님) |
| PPO 스코프 | **지형 돌파만** 학습 (점프, 틈, 턱, 터널, 다리, 경사, 틈새). 미로 해결은 A*/D*(플래너), 기본 보행·자세는 LLC — 학습 대상 아님 |
| 훈련 환경 | 미로가 아니라 **직선 코스 + 지형 모듈 연속 배치**. 훈련 중 플래너 불필요 (유도 벡터 = 코스 축 방향) |
| 초기조건 랜덤화 | **소폭 유지 (A안)**: 스폰 방위 ±15~20°, 횡 오프셋 ±0.15 m, 조주 거리·초기 속도 랜덤. 목적은 "정렬 기술 학습"이 아니라 **훈련↔배포 분포 일치**(코너 출구의 잔여 오차·드리프트 강건성). 완전 정렬 고정 훈련은 배포 시 분포 이탈로 실패 |
| 미로의 역할 | 훈련용이 아니라 **평가·데모 무대**. 이때만 BFS(추후 D* Lite 교체 가능) 유도 벡터 사용 |
| 경로추종 | 유도 벡터 따라가기는 학습 대상이 아님 (LLC + 사소한 매핑으로 충분). 코너·교차로 선택은 전부 플래너 몫 |
| 정밀 정렬 | 외나무다리 중앙 유지, 좁은 틈새 통과 등 cm 단위 작업은 **센서(높이스캔·라이다)를 보는 PPO**가 담당. 거리장은 해상도상 정밀 유도 불가능하며 그럴 필요도 없음 |
| BFS 그리드 | 셀 0.1 m 통일 + 쌍선형 보간(보상·유도 벡터의 연속성 확보). **통과 가능성은 지오메트리 래스터화가 아니라 미로 생성기의 의미 정보로 직접 마킹** (좁은 틈새는 인플레이션 없이 통과 가능 처리, 낙차·허공은 통과 불가 처리) |
| PPO 입력 | 장애물의 "정답 파라미터"가 아니라 **센서 관측**. 지형 인지는 정책이 센서로 수행 (FSM 모드 one-hot은 선택적 보조) |
| LLC 명령 | **8D 연속** (gait는 trot 고정): vx, vy, v_yaw, height, step_freq, footswing, pitch, stance_width. 지형별 주역 — 터널: height / 틈·턱: footswing / 다리·틈새: stance_width / 경사: pitch. ⚠️ **점프는 스코프 아웃** — 단계 0.5 실측에서 pronk가 몸통을 띄우지 못하고(정점 상승 +0.001 m) MJX에서는 전복까지 유발함. 틈은 **걸어서 넘는 폭**으로 제한 |
| 미학습 차원 | `duty`·`roll`은 **이 체크포인트에서 상수로 학습**되어 명령해도 무효 — 액션에서 제외. gait는 `binary_phases`로 양자화되어 **연속 보간 불가**. 근거는 §5.1 |
| 계층 분리 근거 | 성능이 아니라 **학습 예산·검증 용이성·LLC 재사용**을 위한 의식적 선택. 명령 병목(발 위치를 직접 명령 불가)이 성능 상한을 결정 — 극한 지형이 목표면 인지형 단일 정책(관절 레벨)이 연구 표준임을 인지한 상태의 트레이드오프 |

## 1. 전체 아키텍처

```
[평가 시]  미로 생성기 ──▶ BFS 거리장(0.1m, 오프라인) ──▶ 유도 벡터
[훈련 시]  직선 코스   ──▶ 유도 벡터 = 코스 축 방향  ──────┐
                                                          ▼
┌─────────────────────────────────────────────────────┐
│                     HLC (10 Hz)                     │
│  [인지 모듈]          [모드 관리 FSM]                │
│  · 2D 라이다 rays  ──▶ · 지형 모드 판별              │
│  · 높이 스캔 grid      · z/속도 상·하한 설정          │
│  · 클리어런스 스캔     · 낙상 감지 → 종료             │
│  · 유도 벡터                 │                       │
│        │                     ▼                      │
│  [내비게이션 정책 (RL, PPO)] — 지형 돌파 담당         │
│        │  raw action (8D 연속)                       │
│        ▼                                            │
│  [명령 필터] 클리핑 · slew-rate 제한 · LLC 분포 보장  │
└──────────────────────┬──────────────────────────────┘
                       │ 8D 연속 → 15D 명령으로 전개:
                       │   vx, vy, v_yaw, height, step_freq,
                       │   footswing, pitch, stance_width
                       │   (gait=trot(0.5,0,0), duty=0.5, roll=0.0,
                       │    stance_length=0.45 고정)
┌──────────────────────▼──────────────────────────────┐
│                LLC (50 Hz, frozen)                  │
│  proprioception + command ──▶ 12개 관절 목표각        │
└──────────────────────┬──────────────────────────────┘
                       ▼
                  MJX 물리 시뮬레이션
```

구조: **단일 RL 정책 + FSM은 감독자(supervisor)** 하이브리드.
- FSM은 조종하지 않는다. ① 지형 모드 one-hot을 관측에 제공, ② 모드별 명령
  상·하한 강제, ③ 전복·추락·교착 시 에피소드 종료 — 이 세 가지만 담당.
- Phase 1은 FSM 없이 end-to-end로 돌려보고, 실패하는 지형에만 제약을 추가.

## 3. 센서 구성 (Colab 제약: 카메라·이미지 처리 배제)

> **구현 방식: 해석적 질의 우선, `mjx.ray`는 검증용 대체 백엔드.**
> 지형을 §4처럼 **우리가 box 파라미터로 생성**하므로, 광선 추적 없이 동일한 값을
> 닫힌 형태로 계산할 수 있다 (높이 = box 상면 z의 조건부 max, 거리 = ray–AABB slab 교차).
> 이득: ① `mjx.ray`의 hfield/mesh 미지원 제약과 무관 ② 비용이 질의점×box 수의 단순
> 행렬 연산으로 예측 가능 ③ **물리와 센서가 같은 파라미터 배열을 읽으므로 불일치가
> 원천 차단**된다 (hfield를 물리에 주입하던 방식에서 실제로 겪은 문제).
> 두 백엔드는 동일 시그니처로 구현하고, `mjx.ray` 쪽은 값 일치 테스트에만 쓴다.

### 3.1 2D 라이다 (수평)
- 몸통 높이 수평 **16~32 rays**, FOV 270°(전방 중심), 최대 4 m.
- 지형은 전부 box 프리미티브로 조립 (§4) → ray–AABB 해석적 교차.
- 출력 min(d, d_max)/d_max 정규화.

### 3.2 하향 높이 스캔 (핵심 센서)
- 로봇 기준 전방 1.2 m × 좌우 0.8 m, **9×7 grid** 하향 질의 (초기 구현은 7×5=35로 시작).
- 틈 감지, 외나무다리 중앙 정렬, 좁은 틈새 인지의 정밀 정보원.
  cm 단위 작업은 전부 이 센서 기반 (거리장 아님).

### 3.3 상향 클리어런스 스캔
- 몸통 위 3~5 지점 상향 질의. 터널 감지 + z 낮추기의 근거.

### 3.4 Proprioception
- 중력 벡터, 몸통 선속도/각속도, z 추정, 직전 HLC 명령.
- **관절각은 넣지 않는다** (LLC 소관 — 차원 증가 + 보행 위상 과적합 위험).

### 3.5 유도 벡터 (목표 센서 대체)
- 평가: BFS 거리장의 쌍선형 보간 기울기를 로봇 요 기준으로 회전한 (cosφ, sinφ)
  + 정규화된 잔여 거리.
- 훈련: 코스 축 방향을 동일 형식으로 제공 (분포 일치를 위해 형식 통일이 중요).

## 4. 지형 생성

### 4.1 훈련: 직선 코스

> ⚠️ **아래 원안의 파라미터 범위는 전부 폐기됐다 (2026-07-29, A안).** 그 값들은
> 설계 시점의 **희망이었고 측정된 적이 없다.** 실측된 틈 상한은 **0.15 m**로
> 원안 상단(0.7 m)의 21%다. 도약은 원리적으로 불가능함이 확정됐다.
>
> **지형 파라미터의 단일 진실 공급원은 이제 `wtw_nav/terrain/limits.py`다.**
> 이 문서의 숫자를 코드로 옮기지 말 것 — 반대로, 실측이 끝날 때마다 `limits.py`를
> 갱신하고 여기는 참조만 한다. 미측정 지형은 `validate()`가 **거부한다**(조용히
> 잘라내지 않는다 — 잘라내면 정책 정체의 원인을 영영 못 찾는다).
>
> 원안이 왜 위험한가: 원리적으로 불가능한 과제를 커리큘럼에 두면 정책은 영원히
> 실패하고 우리는 그것을 "학습이 덜 됐다"로 오진한다. P1에서 도달 불가능한
> 코스(20 m/30 s)에 6.5M 스텝을 태운 것이 정확히 그 사고였다.

- 복도(폭 ~2 m)에 지형 모듈을 연속 배치. **살아남은 모듈과 범위는 `limits.report()`**:

  ★ 실측 4종 전부에서 **낙상 0건**이다. 한계를 정한 것은 전복이 아니라 추진

  "넘다가 넘어짐"이 아니라 **"넘지 못하고 갇힘"** 이다.

  ⚠️ BEAM의 옛 판정 "실패 모드가 표류라 거의 확실히 불가"는 한때 보류했다가
  **실측으로 되살아났다** — 다만 근거가 다르다. 옛 근거는 "표류가 발산한다"였고,
  진로 유지기가 그것을 잡았다(3.33 → 0.22 m). 새 근거는 **정상상태 오차**다:
  `heading_hold`는 적분항이 없는 P 종속 루프라 상수 요속 편향(ω≈0.118)을 제거하지
  못하고 `y_ss = ω/(k_psi·k_y) = 0.157 m`가 남는다. 실측에서 다리 위 표류 0.297 m가
  실패한 다리의 **반폭 0.275 m를 넘었고**, 발은 다리 위에 있었다(다리 밖 착지 0.8%).
  즉 재고 있던 것이 다리 폭이 아니라 제어기였다. 상세는 `hlc_plan.md` §4.2e.

  피하기 위해 geom 수 고정, pos/size만 랜덤화.
- **초기조건 랜덤화 (A안, 소폭)**: 스폰 방위 ±15~20°, 횡 오프셋 ±0.15 m,
  조주 거리·초기 속도 랜덤. 정렬 기술을 가르치는 게 아니라 "코너 출구의
  잔여 오차" 분포를 재현하는 도메인 랜덤화 — 학습 난이도를 거의 올리지
  않는 강건성 보험이므로 생략 금지. (평가에서 코너 직후 지형 실패가 몰리면
  범위 확대)
- 지형 파라미터는 커리큘럼 변수 (레벨 ↑ → 틈 넓게, 다리 좁게, 터널 낮게).

### 4.2 평가: 미로
- 셀 기반 미로(통로 2 m). 통로 셀에 지형 타입 배정. 훈련에는 사용하지 않음.

### 4.3 BFS 거리장 (평가용, 오프라인 1회)
- 셀 **0.1 m** 통일. 16 m × 16 m 미로 = 160×160셀, numpy 밀리초 수준 — 해상도에
  상한 압력 없음.
- 통과 가능성은 **생성기 의미 정보로 직접 마킹** (래스터화·인플레이션 추정 금지):
  - 일반 벽: 안전 마진 포함 통과 불가
  - 의도된 좁은 틈새(SLIT): 인플레이션 없이 통과 가능 — 표준 인플레이션은
    몸 폭 수준의 틈을 막아버리므로
  - 낙차·다리 옆 허공: 통과 불가 (유도 벡터가 다리 축과 평행해지도록)
- 읽기는 항상 쌍선형 보간 → 유도 벡터·거리값이 연속.
- 위험 지형 셀의 비용은 균일하게 (우회 선호를 심으면 돌파 학습 기회가 사라짐).

## 5. RL 문제 정의

### 5.1 관측 / 행동
- 관측 (~120차원): 라이다(32) + 높이스캔(63) + 클리어런스(5) + proprio(~12)
  + 유도 벡터(3) + 직전 명령(9) + gait 유지 카운터(1) + 모드 one-hot(7, FSM 지형 분류)
  - 장애물의 종류·파라미터 같은 특권 정보는 정책에 주지 않는다 — 지형 인지는
    센서로 수행해야 훈련 코스 ↔ 평가 미로 일반화가 성립.
- 행동: **연속 8D (tanh 스케일)**
  `vx, vy, v_yaw, height, step_freq, footswing, pitch, stance_width`
  **gait는 trot 고정.** 원안은 여기에 이산 1D(trot/pronk)를 더했으나, 단계 0.5 실측에서
  pronk가 **도약을 만들지 못하면서 MJX에서는 전복까지 유발**하는 것이 확인되어 제외했다
  (`llc_port_debug.md` §8). 이득이 없는데 실패만 유발하는 선택지를 정책에 열어줄 이유가 없다.

  **★ 액션 범위의 근거 ★**
  범위는 반드시 **체크포인트에 동봉된 `parameters.pkl`(이 가중치를 만든 config 그 자체)과
  `curriculum/distribution.pkl`(실제 도달한 명령 영역)** 에서 읽는다.
  `scripts/train.py`를 근거로 쓰지 말 것 — 리포에 들어있는 스크립트일 뿐 이 가중치를
  만들었다는 보장이 없다. 재확인 절차는 `hlc_plan.md` 부록 B.

  WTW 명령 범위는 세 겹이며 혼동하면 안 된다:
  `lin_vel_x=[-1,1]`(커리큘럼 **시작** 영역) ≠ `limit_vel_x=[-5,5]`(확장 **상한**)
  ≠ `distribution.pkl`의 weights>0(**실제 도달 영역** ← 이것이 근거).

  **조작 불가 차원 (이 체크포인트 한정)**
  - `duty`, `roll` — `gait_duration_cmd_range=[0.5,0.5]`, `body_roll_range=[-0.0,0.0]`.
    샘플링 범위와 커리큘럼 상한이 **둘 다 폭 0** → 학습 내내 상수만 관측. 해당 입력
    채널은 사실상 죽어 있어 어떤 값을 넣어도 유의미한 거동 변화를 기대할 근거가 없다.
    ⚠️ WTW의 *인터페이스*는 15D로 duty·roll을 포함한다 — **인터페이스에 슬롯이 있다는
    것과 그 슬롯이 학습됐다는 것은 별개다.** 논문의 duty 스윕 시연은 별도 config로
    학습된 다른 정책이다.
  - `gait` — `binary_phases=True`가 `(phase,offset,bound)`를 `{0,0.5}`로 양자화.
    4개 프리셋(trot/pronk/pace/bound)에서만 학습됨 → **연속 보간은 분포 이탈**.
    trot=(0.5,0,0), pronk=(0,0,0). 한때 이산 선택 액션으로 열려 했으나,
    단계 0.5에서 pronk가 도약을 못 만들고 전복만 유발해 **trot 고정**으로 확정.

  **vx–v_yaw 결합 제약 (상자 아님)**
  도달 영역이 마름모꼴이라 직진이 빠를수록 회전 여유가 줄어든다
  (trot 고정이므로 **trot의 마름모**를 쓴다: vx ±2.38, v_yaw [−3.33, +2.86]).
  `|vx|/VX_MAX + |v_yaw|/YAW_MAX ≤ 1`로 L1 제약을 걸고, 넘으면 원점 방향으로 축소한다.
  **미소 명령 데드존**: `‖(vx,vy)‖ ≤ 0.2`인 명령은 LLC 훈련 시 0으로 치환된 뒤
  학습됐으므로 미학습 구간 — 0으로 스냅한다.

  **학습 커리큘럼**: 처음부터 전 차원을 열지 않는다. **4D(vx, vy, v_yaw, height)만 열고
  모든 지형을 먼저 시도**, 나머지는 기본값 고정으로 두고 실패하는 지형이 요구하는
  차원부터 하나씩 개방 (다리 실패 → stance_width, 틈 실패 → footswing,
  경사 실패 → pitch, 점프 필요 → gait+step_freq). 전부 한 번에 열면 탐색이 발산 —
  어떤 차원이 어떤 지형을 풀었는지가 그대로 분석 결과물이 됨.
- 네트워크: MLP 3층(512-256-128), tanh 가우시안. Critic 동일 구조 별도.
  순환 구조는 부분관측 문제가 확인될 때만 도입.
- 주기: LLC 50 Hz / HLC 10 Hz, 명령 1차 저역필터(α≈0.3).
  (gait가 trot 고정이 되면서 "이산 차원에는 저역필터 금지" 조항은 불필요해졌다.)

### 5.2 보상 — "유도는 방향, 기술은 종료 조건이 가르친다"
- progress: 유도 방향으로의 진행량 `k·(d(t−1)−d(t))` (훈련: 코스 축 거리,
  평가엔 보상 불필요). potential-based.
- 종료 페널티(−5): 전복, 추락, 교착. **틈새·다리 돌파 기술이 학습되는
  메커니즘은 progress(건너려는 동기) × 추락 종료(어설픈 시도의 대가)의 조합**
  — BFS/유도는 "어디로"만 알고 "떨어지면 안 됨"은 종료 조건이 가르친다.
- 보조: 도달 보너스(+10), 시간 페널티(−0.01/step), 몸통·허벅지 충돌 페널티,
  명령 급변 페널티.
- 종료: 코스 완주(성공), 전복, 추락, 타임아웃(~60 s).

### 5.3 학습
- Brax PPO, 병렬 2048~4096 env. LLC frozen MLP를 env step(jit) 내장.
- T4 가능, A100이면 수 시간 내 전체 커리큘럼 기대.

## 6. FSM (모드 관리자) — Phase 2

| 모드 | 진입 조건 (예시) | 제약 |
|------|------------------|------|
| NORMAL | default | 없음 |
| TUNNEL | 전방 클리어런스 < 0.4 m | z ≤ 0.18, vx ≤ 0.4 |
| BEAM | 좌우 낙차 > 0.3 m & 지지폭 < 0.4 m | \|vy\| ≤ 0.1, \|wz\| ≤ 0.5, vx ≤ 0.3 |
| GAP | 전방 깊은 낙차 띠 | vx 하한 0.4 (멈칫거림 방지) |
| STEP | 전방 높이스캔에 상승 단차 | footswing 하한, vx ≤ 0.5 |
| SLIT | 좌우 라이다 근접 & 통로 폭 < 0.45 m | vx ≤ 0.3, \|wz\| ≤ 0.3 |
| SLOPE | 발밑 평균 경사 > 8° | vx ≤ 0.5, z 소폭 하향 |

- `jnp.where` 기반 분기 + 히스테리시스(채터링 방지).
- 모드 one-hot 제공(①)은 거의 공짜 이득, 명령 제한(②)은 탐색을 좁히는
  양날의 검 — 실패하는 지형에만 적용.
- RECOVERY는 sim-only이므로 기립 정책 대신 에피소드 종료로 처리.

## 7. 구현 로드맵

| 단계 | 내용 | 검증 기준 |
|------|------|-----------|
| 0 | frozen LLC 로드·추론 유틸 (`body` + **`adaptation_module` 둘 다 필요**) | torch↔JAX 출력 차 < 1e-4 / trot `(0.5,0,0)`으로 vx=0.8 명령 시 실측 0.6~0.9 m/s 직진, 5 s 무낙상 |
| 0.5 | 명령 스윕으로 각 차원 극값 추종 확인 | height 하한에서 낮은 자세 / stance_width 하한·상한 / footswing 상한에서 발 높이 증가 / **pronk `(0,0,0)`에서 4足 동시 체공** ← duty 고정 상태의 점프 가능성 판정 / vx–yaw 마름모 경계 3점 추종 오차 |
| 1 | 평지 직선 코스 + 유도 벡터 추종 env (장애물 X) | 성공률 > 95% — 인터페이스 검증 |
| 2 | 센서 3종 + 지형 모듈 1종씩 단독 학습 | 지형별 성공률 > 80% |
| 3 | 모듈 연속 배치 + 초기조건 랜덤화 + 커리큘럼 (+필요 지형만 FSM 제약) | 전 지형 > 80% |
| 4 | 평가 미로 + BFS 거리장 유도 + 도메인 랜덤화 검증 | 미로 성공률 > 70%. **실패가 코너 직후 지형에 몰리면 초기조건 랜덤화 범위 확대** |
| 5 | 평가/시각화 노트북 (성공률, 도달시간, 낙상 원인) + 필요시 D* Lite 데모 | — |

- 단계 0의 원안은 "WTW LLC를 전 차원 랜덤 샘플링으로 **재훈련**"이었으나, 공개
  체크포인트를 그대로 쓰는 쪽으로 변경했다(재학습 0시간).
- ⚠️ **단계 0.5 판정 결과 (2026-07-28): 도약 불가.** pronk에서 4足 체공은 20~30%
  나오지만 **몸통 정점 상승이 +0.001 m**로 사실상 뜨지 않는다(다리를 접어 발만 뗌).
  체공 중 수평이동 상한 **0.13 m**. → **틈 폭 상한을 "걸어서 넘는 범위"로 재설정해야
  하며, §4.1의 GAP 0.1~0.7 m 중 상단은 달성 불가**다. P2에서 실제 지형으로 실측해
  상한을 정한다. 도약이 정말 필요하면 duty를 열어 LLC 재훈련(비용 큼).
  수치는 `llc_port_debug.md` §8.
- ★ **2026-07-29 방향 확정: A안 — LLC는 고정하고 불가능한 지형지물을 지운다.**
  실측 결과 HLC 8D 명령 전체가 사줄 수 있는 지형 능력은 **약 3 cm**다
  (footswing을 4배 올려 턱 +3 cm를 얻고 틈 −5 cm를 잃는다). 근본 원인은 계층
  분리 자체가 아니라 **지형 정보가 발 착지를 결정하는 계층에 닿지 않는다**는
  것이다 — 발 착지는 50 Hz 결정인데 10 Hz 8D 명령으로는 표현할 수 없다.
  그럼에도 A를 먼저 하는 이유: 센서·지형 모듈·HLC 루프·평가 미로는 어느 방향으로
  가든 필요하고, LLC를 건드리는 안(높이스캔 입력 추가 후 미세조정)은 그것들이
  있어야 **검증**할 수 있다. 즉 A는 다른 안의 선행 작업이지 대안이 아니다.
  단계 2·3의 "전 지형"은 이제 `limits.py`에서 **실측으로 살아남은 지형**을 뜻한다.
  ⚠️ **위의 "약 3 cm"를 지형 일반으로 읽지 말 것 (2026-08-09).** 그것은 `gap`
  하나의 수이고, gap은 **지면이 없는 유일한 지형**이라 가장 불리한 표본이었다.
  실측을 마친 셋은 통과 가능했다 — 경사 20°, 터널 0.291 m, 요철 진폭 0.06 m
  (평균 단차 0.040 m). "지형 정보가 발 착지 계층에 닿지 않는다"는 진단은 그대로
  맞지만, 그 결과가 **모든 지형에서 3 cm**인 것은 아니다.
- 상세 실행 계획·모듈 인터페이스·리스크는 **`hlc_plan.md`** 참조.
